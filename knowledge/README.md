# knowledge/ — 專案知識（4 份文件）

| 文件 | 是什麼 | 什麼時候寫 | 誰觸發 |
|---|---|---|---|
| `brief.md` | 專案定義：目標、資料、預測當下能用的資訊、怎麼驗證、何時停止 | 開始前，寫一次 | 你說「define-boundaries」 |
| `data.md` | 每張表是什麼、有哪些坑 | 拿到資料時 | 你說「data-card」 |
| `log.md` | **研究日誌**：每次分析或實驗一段，包含失敗與卡關 | **AI 每次回報結果時自動追加** | AI 自動 |
| `findings.md` | **沉澱下來的結論**，加上給決策者的現況 | 每輪結束 | 你說「round-review」 |

## 你只需要記得一件事

**每輪結束時說「round-review」。** 其他都是自動的：

- **記錄自動發生**：AI 每次回報分析結果，都會在 `log.md` 追加一段；沒有結果、卡住、方向錯了也要記
- **沉澱發生在 round-review**：AI 從 `log.md` 挑出「下次還會用到」的候選，列給你看，**你決定留哪幾條**，留下的寫進 `findings.md`

## 什麼算「值得沉澱」

符合任一條就值得：
- 會改變下一步的決定（「這個特徵沒用，別再試」）
- 會改變對業務的說法（「模型抓不到嚴重延遲造成的差評」）
- 會讓人再踩一次的坑（「這張表一單多列，直接 join 金額會重複」）

只是「跑了一個實驗、分數差不多」的，留在 `log.md` 就好。

可以用 Obsidian 開啟這個資料夾，但不是必要的：這 4 份文件都是一般的 Markdown。
