# 資料科學心法：從問題定義到模型落地

> 大道至簡：**問題定對、切分做對、特徵講得出理由、模型最後才挑。**

## 寫給讀者的話

很多人學資料科學的路徑是這樣的：先學 pandas，再學 scikit-learn，接著在 Kaggle 上跑幾個模型，看著分數一點一點往上爬。這條路能讓你很快「做出東西」，但會留下一個隱憂——你知道**怎麼做**，卻不一定知道**為什麼要這樣做**。

這個隱憂平常看不出來，直到某一天：模型在驗證時分數很漂亮，上線後卻完全失靈；或是主管問你「為什麼選這幾個特徵？」「你怎麼確定這個進步不是運氣？」，你答不出來。

這本書想補的就是這一塊。它不教語法，也不推導數學，而是把一個預測專案從頭到尾會遇到的**判斷題**整理出來：這題該怎麼定義？資料該怎麼切？這個特徵能不能用？這兩個模型誰比較好？每一個判斷，我們都會先講「如果不這樣做，會出什麼問題」，再講「所以該怎麼做」。理解了前因後果，你不用背規則，也能在新的題目上自己推出正確的做法。

## 怎麼讀這本書

- **照順序讀**。後面的章節會用到前面的觀念：第 3 章的切分方式，取決於第 1 章定義的「預測時點」；第 4 章的特徵能不能用，又取決於第 3 章的洩漏觀念。
- **遇到不懂的術語，先查[術語表](glossary.md)**。每個術語第一次在正文出現時都會解釋，術語表把它們集中起來，方便回查。
- **讀到「先預測」的地方，真的先停下來猜**。被推翻的直覺，比被告知的結論記得更牢。
- **做習題**。每章習題分三種：概念題確認你理解原理，應用題讓你在新情境套用，思辨題沒有標準答案，是用來討論的。

## 教學建議

1. **先觀念、後技巧**：每節先講「為什麼需要」，再講「怎麼做」。學員接受了問題，才會接受解法。
2. **先預測、後揭曉**：講案例前先請學員猜結果，再公布答案。
3. **錯誤示範與正確示範並排**：洩漏、切分、相關與因果，都適合用對照的方式呈現。
4. **教科書講完，再進入實戰**：把心法套進一個具體專案，學員才會看到這些觀念在真實情境裡的樣子。

## 圖文原則

| 原則 | 做法 |
|---|---|
| 圖之前先講為什麼 | 每張圖前面有一段話，說明這張圖要回答什麼問題 |
| 圖之後教讀法 | 每張圖後面有「怎麼讀這張圖」，說明從哪裡看起、要記住哪一點 |
| 一張圖不超過 7 個方塊 | 超過就拆成兩張，或改用表格 |
| 一章一張主視覺（★） | 學員回想這章時，腦中只需浮現一張圖 |
| 可版控 | 流程與決策樹用 Mermaid；示意插畫另存圖檔 |
