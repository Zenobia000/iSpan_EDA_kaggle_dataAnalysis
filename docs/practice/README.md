# 落地手冊：把心法用在一個真實專案上

## 這本手冊要解決什麼問題

讀完教科書，學員通常會有一種落差：每個觀念都聽懂了，但面對一份真實資料時，不知道第一步要做什麼、做完要存在哪裡，也不知道什麼時候算完成。觀念和操作之間少了一座橋。

這本手冊就是那座橋。它用一個已經設計好的**專案模板**，把教科書的每一章對應到一個具體的操作階段。模板事先規定好資料夾、文件與工作規則，學員只要照著階段走，就會自然地把「定義問題 → 探索 → 特徵 → 實驗 → 審查」的心法做過一遍。

這本手冊和教科書的分工如下：

| | 教科書 `textbook/` | 落地手冊 `practice/`（本書） |
|---|---|---|
| 回答的問題 | 為什麼要這樣做？原理是什麼？ | 在這個專案裡，具體怎麼做？ |
| 會不會提到工具 | 不提 | 會提：資料夾、文件、AI 指令 |
| 能不能單獨讀 | 可以 | 建議先讀對應的教科書章節 |

## 什麼是「專案模板」

專案模板是一個**空的專案資料夾**，裡面沒有分析程式，只有三樣東西：

1. **資料夾分層**：每個資料夾都有一份 `README.md`，寫明這裡放什麼、誰可以寫。這樣不管是人還是 AI，都知道一個檔案該放哪裡。
2. **專案知識文件**：`knowledge/` 裡的 4 份文件，記錄專案的定義、資料說明、研究過程和結論。
3. **AI 的工作規範**：告訴 AI 助手（Claude Code 或 Codex）在這個專案裡應該怎麼工作、哪些事情不能做。

為什麼要用模板，而不是每次從空白資料夾開始？因為初學者最常出錯的地方，往往不是模型，而是流程：忘了先定義問題、把探索用的程式和正式程式混在一起、做了實驗卻沒有紀錄。模板把這些流程規則事先寫好，讓人可以專心思考。

## 給講師：建議的上課方式

每一個單元依「觀念 → 技巧 → 落地」的順序進行：

1. **講觀念**（教科書）：先讓學員理解問題為什麼存在、不處理會發生什麼事。
2. **講技巧**（教科書）：介紹解決這個問題的方法與判斷準則。
3. **帶落地**（本手冊）：打開模板，示範同一個觀念在專案裡長什麼樣子。每章的「講師口述要點」列出值得口頭強調的地方，「概念圖」適合投影在螢幕上邊畫邊講。

建議不要跳過第 1 步直接示範操作。學員如果不知道一個步驟為什麼存在，只會照著背指令，換一個專案就不會用了。

## 每一章的結構

每一章都依同樣的順序撰寫，學員翻到任何一章都知道去哪裡找什麼：

1. **這一章要解決什麼問題**：用一個情境說明，如果沒有這個步驟會出什麼錯
2. **心法回顧**：用兩三句話連回教科書
3. **本章在整個流程的位置**
4. **步驟**：每一步都先說為什麼，再說怎麼做、產出什麼、怎樣算完成
5. **概念圖**：每張圖前面說明為什麼需要它，後面說明怎麼讀
6. **用到的 skill 與 subagent**
7. **講師口述要點**
8. **檢核清單**
