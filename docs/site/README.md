# docs/site/：落地手冊的網頁版

`index.html` 是一個單一檔案的靜態網站：CSS 與 JavaScript 都寫在檔案裡，不需要安裝套件，也不需要建置步驟。它把 `docs/practice/` 壓縮成「先看摘要、點開才看細節」的分層教程。

## 設計說明：版面從內容的哪裡長出來

| 內容的特性 | 對應的形式 |
|---|---|
| 專案依固定順序推進，中間有三道人類閘門 | 古埃及墓壁的**橫帶敘事**（register）：一條帶子是一層流程，由左往右讀；第二層（一輪迭代）只在點開後出現 |
| 11 個 skill 是有固定名字、會被反覆呼喚的「名號」 | **王名圈**（cartouche）外框：圓角框加上一端的豎線，只用在 skill 與 subagent 名稱 |
| 人類決定、AI 執行、已驗證，是三種不同的責任 | 埃及顏料各管一件事：**紅玉髓紅**＝人類閘門，**青金石藍**＝AI 執行，**孔雀石綠**＝已驗證，**赭金**只做裝飾與焦點框，不用在文字 |
| 規則要經得起長期查閱 | 莎草紙底色加淡淡的交織纖維紋理，墨黑文字；頁首頁尾用一條細的色塊飾帶（frieze）收邊 |

刻意不做：人物或神祇圖像、象形文字裝飾、金色漸層、emoji。可讀性優先：正文 16–17px、標籤至少 14px，正文對比度至少 4.5:1；中文使用「」引號與 `line-break: strict`。

字體方面，標題用 EB Garamond 搭配 Noto Serif TC，內文用 IBM Plex Sans 搭配 Noto Sans TC，指令區塊用 IBM Plex Mono。字體從 Google Fonts 載入，離線時改用系統的宋體與黑體。

## 資訊架構（漸進式披露）

1. **總覽**：一句話主張、新手只要記的兩件事、八個名詞（點開看細節）
2. **協作模型**：第一層是整個專案的流程，點「一輪迭代」展開第二層，再點任一步看第三層細節
3. **操作流程（第 0–6 站）**：拿到題目就照這一條路走。每站上半部是「你要做的事」（人類要做什麼、為什麼、對 AI 說的完整指令與複製按鈕、產出、完成訊號），下半部是「AI 怎麼做」的子步驟細節，最後是檢核清單（勾選存在 localStorage）與講師口述要點。第 2–5 站標示為「一輪迭代」
4. **Skill × Subagent 矩陣**：11 個 skill 的總表、skill 與站別的對照、4 個 subagent
5. **資料夾**：互動式的資料夾樹
6. **術語速查**：可以搜尋

網站以分頁呈現（總覽／操作流程／Skill 矩陣／資料夾／術語），每頁底部有上一頁、下一頁。切換由點擊直接驅動，不依賴網址，所以在編輯器預覽裡也能用。深層連結仍可用：`#step-3`（打開第 1 站並展開該動作）、`#stage-4`（第 4 站）、`#stage-4-2`（第 4 站的第 2 個細節）。

## 怎麼開啟

- **本機**：直接用瀏覽器開啟 `docs/site/index.html`，用 `file://` 即可
- **本機伺服器**（「複製」按鈕在 http 下最穩定）：
  ```bash
  python3 -m http.server -d docs 8000
  # 開啟 http://localhost:8000/site/
  ```
- **GitHub Pages**：Settings → Pages → Source 選 `main` 分支、資料夾選 `/docs`，網址是 `https://<帳號>.github.io/<repo>/site/`。頁尾連到 `../practice/*.md` 與 `../textbook/*.md` 的連結，在 Pages 上會顯示 Markdown 原始檔；如果要渲染成網頁，再搭配 MkDocs 發佈

## 維護

網頁內容是 `docs/practice/` 的**壓縮版**：要改內容，先改 Markdown，再同步改 `index.html` 裡 `<script>` 的資料陣列：`STEPS`（使用步驟）、`STAGES`（各階段）、`SKILLS`、`AGENTS`、`F` / `TREE`（資料夾）、`G`（術語）。版面不必動。
