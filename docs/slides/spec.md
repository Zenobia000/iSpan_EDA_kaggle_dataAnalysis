# 投影片設計 spec（三個方向共用）

## 是什麼
把 `docs/textbook/`（資料科學心法：從問題定義到模型落地）做成上課投影片。

## 受眾與場景
- 會用 pandas / scikit-learn、但說不清「為什麼這樣切、為什麼選這個特徵」的學生與轉職者
- 講師在教室投影講解；學員課後也會自己翻閱

## 核心信息
- 大道至簡：問題定對、切分做對、特徵講得出理由、模型最後才挑
- 資料科學的概念用文字很難懂 → **能畫成圖的一律畫成圖**（資訊圖表優先）

## 情感基調
手繪筆記風、簡約、幾何。像一位很會畫圖的老師在白板／筆記本上幫你把概念畫清楚：親切、清楚、不花俏。

## 輸出格式（三個方向統一）
- 1920×1080 HTML deck（多檔架構 + 概覽牆），之後輸出 PDF
- 正文 ≥ 24px、標籤 ≥ 16px、標題 60–120px

## 整份 deck 的結構（使用者指定）
1. 開場：為什麼要學這堂課 / 適合對象 / 先備知識 / 準備工具 / 適合哪些人
2. 每章：章首「學習目標」→ 概念頁（以圖表為主）→ 章末「小結 recap」→「下一章」預告
3. 大總結
4. 最後一頁：術語表；並附參考文獻

## 代表頁（三方向各做這兩頁，同內容只換設計）
1. 「為什麼要學這堂課」（開場敘事頁）
2. 「時間切分：擴張視窗」（概念資訊圖：第 3 章 3.5 節，15 個月資料、3 個 fold + 保留集）

## 已知約束
- 不編造數據；概念圖用教科書中的示意數字
- 單頁不自帶頁碼（由外殼承載）
