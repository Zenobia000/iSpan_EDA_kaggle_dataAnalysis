# 投影片製作 brief（每位製作者必讀）

## 這份 deck 是什麼
把 `docs/textbook/` 做成 1920×1080 的 HTML 投影片。讀者：會用 pandas / scikit-learn、但說不清「為什麼」的學生與轉職者。
**資料科學概念用文字很難懂 → 能畫成圖的一律畫成圖（資訊圖表優先），文字只是註解。**

## 已核准的視覺方向：幾何色塊（不得更改）
- 參考：`slides/02-why.html`、`slides/05-merge-trap.html`、`slides/09-course-map.html`，以及 `../design-demos/dir-2/slides/02-time-split.html`
- 紙色底 `#f3efe6`；墨色 `#1b1b1b`；**靛藍 `ind` #2b4c7e、朱紅 `ver` #e0442b、芥黃 `mus` #e8b53a**；灰 `grey` #a8a296
- 形狀語意全 deck 一致：**方 = 訓練 / 結構 / 正確做法；圓 = 驗證 / 重點；三角 = 保留集 / 警示**；朱紅 + 叉 = 錯誤示範
- 手繪感來自 rough.js（鉛筆排線）；字體 Huninn
- 構圖：一頁一個概念；大圖形當主角；文字在旁邊小欄；留白是構圖

## 檔案規則
- 每頁一個檔案：`slides/<編號>-<英文短名>.html`。**編號只能用分配給你的前綴**（見下方）
- 檔案骨架（照抄）：

```html
<!DOCTYPE html><html lang="zh-Hant"><head><meta charset="utf-8"><title>頁面標籤（概覽牆用，6–10 字）</title>
<link rel="stylesheet" href="../assets/base.css"><script src="https://unpkg.com/roughjs@4.6.6/bundled/rough.js"></script><script src="../assets/draw.js"></script>
<style>/* 本頁專用樣式 */</style></head><body><div class="slide">
  <h1>標題</h1><p class="lead">一句話說明</p>
  <!-- 文字用 class="abs" + style="left/top" 絕對定位 -->
  <div class="read"><em>怎麼讀：</em>從哪裡看起、要記住哪一點</div>
</div><svg class="rough" id="r" width="1920" height="1080"></svg>
<script>const D=Draw('r'); /* D.sq / D.rect / D.ci / D.tri / D.dia / D.line / D.dash / D.arrow / D.curve / D.poly / D.cross / D.bars */</script></body></html>
```

- 繪圖 API 見 `assets/draw.js` 開頭註解。顏色參數可用 `'ind' | 'ver' | 'mus' | 'ink' | 'grey'` 或 `#hex`；第 6 個參數是 rough.js 選項（例：`{fillStyle:'solid'}`）
- **有文字的方塊用淺色實心**：`D.rect(x,y,w,h,'#d9e1ee',{fillStyle:'solid',stroke:D.C.ind,strokeWidth:3})`（淺靛 #d9e1ee、淺朱 #f7d6cf、淺黃 #f7e7c0）。排線填色只用在沒有字的大圖形
- 圖層在文字下方（base.css 已設定），所以文字可以壓在淺色方塊上
- **不要修改 `assets/` 與別人的檔案**。需要新的繪圖函式，在自己的頁面 `<script>` 裡定義

## 硬規則
1. 字級：標題 ≥ 72px（用 h1 預設 80px）；正文 ≥ 26px；標籤 ≥ 22px（`.lbl` 24px、`.note` 24px）
2. **數字只能來自教科書**。教科書沒有的數字不准編；示意圖（例：過擬合曲線的形狀）要在圖旁標「示意」
3. 不放頁碼、進度、全大寫小標籤；01/02/03 只在內容本身是順序時使用；不用 emoji
4. 每個概念頁底部有 `.read`「怎麼讀」一句話（目標頁、小結頁除外）
5. 文字不得互相重疊、不得被圖形蓋住、不得超出畫面；寫完一定要截圖檢查（見下方）

## 每一章固定結構
1. **章首頁** `<前綴>00-goals.html`：左側大字「第 N 章」＋章名＋本章心法（`.lead`）；右側「學習目標」清單（`ul.dots`）；底部一個淺色框寫「本章案例」。配一個大幾何形（每章輪流：方 / 圓 / 三角）
2. **概念頁**：照下方清單，每頁一張主圖
3. **章末小結頁** `<前綴>99-recap.html`：標題「第 N 章小結」，左側 3–5 點重點（教科書「本章小結」），右側一張縮小版的本章主視覺（★）；右下角 `<div class="next">下一章：○○○</div>`

## 檢查流程（每做完 3–4 頁就做一次）
```bash
cd docs/slides/deck
./shoot.sh <你的前綴>                      # 截圖到 shots/
uv run python contact.py <你的前綴> /tmp/<任意名>.png   # 拼成總覽圖，再用看圖能力檢查
```
發現重疊、溢出、太空、太擠 → 修好再截一次。

### 前綴 1xx — 第 1 章 問題分析與拆解（`01_problem_framing.md`）
- 100-goals：案例＝連鎖超市 200 間門市的缺貨預警
- 101-task-canvas ★：左邊區經理的模糊需求（引言），右邊九格任務規格表（前 4 格「決策」用靛色、後 5 格「任務」用黃色），填入教科書案例答案
- 102-t0-timeline：時間線，T0＝每天 08:00 一條朱紅直線；左邊「前一天銷量・進貨」（可用），右邊「當日銷量」（打叉）、「未來 3 天是否缺貨」（答案）；註明「看被觀察到的時間，不是發生時間」
- 103-accuracy-trap：1,000 個小方塊的格子圖，其中 30 個朱紅（3% 缺貨）；「全猜不缺貨：準確率 97%，抓到 0 個」；旁邊說明店長只看前 20 名 → Precision@20、Lift

- 105-baselines：兩種基準（不學習的基準 vs 簡單規則「昨天庫存最低的 20 個」），各回答哪個問題
- 106-stopping：五種停止條件，案例數字（30 次、0.005、連續 2 輪、季底、Lift@20 ≥ 5 倍且贏過規則）
- 107-issue-tree：議題樹（為什麼會缺貨 → 三分支 → 子節點），標 MECE；三種拆解方法
