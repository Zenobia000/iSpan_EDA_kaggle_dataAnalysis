# Knowledge Capture

## 1. 記錄：每次回報結果時自動做（不用等人類要求）

在 `knowledge/log.md` **最下方**追加一段：

```
## R<輪次>-<序號> · <日期> · <這次想回答的問題>
- 做了什麼：（一句話 + 程式位置）
- 結果：（數字，附 run_id）
- 結論：支持 / 推翻 / 不確定 / 卡住
- 坑或困難：（沒有就寫「無」）
- 下一步：
```

- **失敗、卡住、方向錯了一樣要寫**：最值錢的常常是「這條路不通」
- 不改寫舊段落；寫錯了就在下面追加更正
- 數字必須來自真的執行過的程式，並附 `experiments/log.jsonl` 的 run_id；沒跑過的不寫數字

## 2. 沉澱：每輪結束（round-review）時做

1. 讀這一輪的 `log.md` 段落
2. 挑出**候選**，符合任一條才算：
   - 會改變下一步的決定
   - 會改變對業務的說法
   - 會讓人再踩一次的坑
3. 列給人類看，**由人類決定留哪幾條**
4. 留下的寫進 `knowledge/findings.md`：
   - 結論 → 「發現」表（一句話、標題就是結論、附證據與對業務的意義）
   - 沒用的嘗試 → 「試過但沒用的」表
   - 更新「給決策者」三行
5. 資料的坑 → 也補進 `knowledge/data.md` 的「坑」

## 不要做
- 為每個實驗另開檔案
- 把「分數差不多」的實驗寫進 findings
- 修改 `knowledge/brief.md`（那是人類的）
