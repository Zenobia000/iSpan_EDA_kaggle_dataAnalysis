# 假設驅動 EDA

源自武器庫「McKinsey 議題樹」。原則：**先寫預期，再跑程式。** 沒有預期的圖表不畫。

## 步驟

1. 用議題樹拆「為什麼訂單會拿到差評？」到 L3（物流 / 商品 / 賣家 / 價格與付款 / 顧客）。
2. 每個葉節點寫成一張假設卡（模板如下），**跑程式前**先填「預期」。
3. 資料：`from olist_course.data.build_base import build_eda_table`；它含 T0 後欄位（`delivery_delay_days`、`order_status`），
   **只能用來理解機制，不可當特徵**。
4. 每張卡至少做一次「分組比較」與一次「控制混雜因素後再比較」（例：遲到 vs 差評，在相同 `est_delivery_days` 分箱內再比一次）。
5. 結論只能是：支持 / 推翻 / 證據不足。並寫出「這張卡能不能變成 T0 可用的特徵？」

## 假設卡模板

```markdown
#### H<n>：<一句話假設>
- 機制：<為什麼會這樣>
- 預期：<跑之前寫，例：遲到訂單差評率 > 3 倍>
- 檢驗：<groupby / 分箱 / 交叉表 + 控制變數>
- 結果：<數字>
- 結論：支持 / 推翻 / 證據不足
- 競爭解釋：<另一個也能解釋這個相關的原因（混雜因素）>
- T0 可用的代理特徵：<例：遲到在 T0 不可知 → 用 est_delivery_days、customer_seller_km 當代理>
```

## Lab1 必做：相關 ≠ 因果

「遲到 → 差評」相關極強。要求學員提出至少兩個競爭假設（例：偏遠地區同時造成遲到與期待落差；
特定品類同時難配送又容易不滿意），並用分層比較檢查。

## 驗收

3 張以上假設卡，至少 1 張被推翻或證據不足；每張都標示 T0 可用的代理特徵或「無」。

## 沉澱
每張假設卡寫成 `knowledge/30_Hypotheses/H-xxx <標題>.md`（模板 Hypothesis）；有結論的寫一則 Finding（knowledge-capture skill）。
