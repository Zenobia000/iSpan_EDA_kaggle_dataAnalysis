# Report Writer

源自武器庫「分析報告製作」。報告讀者是**業務主管**，不是資料科學家。

## 資料來源（全部要能追溯）

- `read_log()`：所有實驗紀錄（含 git sha）
- 最終模型的 `compare()` 表、permutation importance、slice_report
- 本地 leaderboard 分數（若講師已公布）

## 結構

```markdown
# <一句話結論：例：在下單當下即可找出 5% 高風險訂單，命中率為隨機的 2.9 倍>

## 1. 決策建議（3 點以內）
## 2. 模型能做到什麼
- Precision@5% / Lift@5%，換算成「每 1000 筆關懷名單中有幾筆真的會差評」
## 3. 證據
- Ablation 表（只放 robust 的增益）
- 前 5 個重要特徵與商業解讀
## 4. 我們排除了什麼
- 試過但無效的特徵、被推翻的假設、被擋下的洩漏（例：實際送達日讓 PR-AUC 0.29→0.58 是假的）
## 5. 限制與風險
- 相關 ≠ 因果：模型找出高風險訂單，不代表關懷能降低差評（需 A/B test）
- 分布偏移：adversarial validation 結果與對策
## 6. 下一步
```

## 驗收

每個數字都對得到 `experiments/log.jsonl` 的一筆紀錄；第一句話讓主管不讀後文也能做決定。
