# Leakage Audit

## 一句話原則
**預測那一刻，這個值存在嗎？算出它用到的每一筆資料，那一刻都已經被觀察到了嗎？**

## 清單（逐項回答，附證據）
| # | 檢查 | 怎麼查 |
|---|---|---|
| 1 | 欄位是否在 `knowledge/brief.md` §3 的不可用清單 | 對照 §3 |
| 2 | 計算過程有沒有用到 T0 之後才被觀察到的事件 | 讀程式 |
| 3 | 歷史聚合是否嚴格 `< T0`，並排除目標列自己 | 擾動測試 |
| 4 | target encoding / 平滑先驗是否用了驗證或 holdout 的答案 | 讀程式；必須放進 Pipeline |
| 5 | 前處理是否只在訓練 fold 上 fit | 確認 Pipeline |
| 6 | 切分：同一實體是否同時出現在 train 與 valid（群組洩漏） | 檢查群組欄位 |
| 7 | 時間序列：lag / rolling 視窗是否包含預測起點或之後 | 擾動測試 |
| 8 | 異常增益：單次大幅進步，或單一特徵的 importance 遠超其他 | 實驗紀錄、permutation importance |

## 擾動測試怎麼寫
見 `tests/README.md`。第一次需要時，在 `tests/test_leakage.py` 寫：
1. 一份合成的小資料（不依賴下載）
2. 依「資訊可得性」表竄改 cutoff 之後才被觀察到的資訊（只往後移）
3. 對每個特徵群組斷言：cutoff 之前的列特徵不變
4. 一個**故意洩漏**的反例群組，斷言測試抓得到

## 回報
`判定：乾淨 / 洩漏 / 可疑` → 證據（清單項目、測試輸出、檔案:行號）→ 修法（T0 可得的替代特徵）。
