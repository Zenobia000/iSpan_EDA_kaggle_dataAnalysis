# Hypothesis-driven EDA

**先寫預期，再跑程式；沒有預期的圖不畫。**

## 步驟
1. 把「為什麼目標會發生？」拆成議題樹（到可驗證的葉節點）
2. 每個葉節點寫成一個問題，**跑程式前**先寫下預期；結果追加到 `knowledge/log.md`
3. 程式放 `notebooks/<輪次>-<主題>`；可以用預測時點之後的欄位**理解機制**，但要標註「T0 不可得」
4. 每張卡至少：一次分組比較 + 一次**控制混雜因素**的分層比較；報告樣本數
5. 結論只能是 supported / refuted / inconclusive，並寫出：
   - 競爭解釋（另一個也能解釋這個相關的原因）
   - **T0 可用的代理特徵**（機制本身在 T0 不可得時尤其重要）

## 驗收
被推翻或證據不足的假設也要留下；每張卡都標示代理特徵或「無」。
